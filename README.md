# Windows Cache Cleanup

Скрипт для Windows 10/11: показывает известные кэши и умеет удалять старые файлы, когда их суммарный объём достиг порога. Нужен штатный Windows PowerShell 5.1 или PowerShell 7. Зависимостей и подключения к сети нет.

## Быстрый запуск

Открой PowerShell в папке скачанного репозитория. Обычный запуск **только показывает отчёт**:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\windows-cache-cleanup.ps1
```

Предварительный просмотр удаления:

```powershell
.\windows-cache-cleanup.ps1 -Auto -ThresholdGB 20 -MinAgeDays 7 -WhatIf
```

Удалить подходящие файлы, если их суммарно не меньше 20 ГиБ:

```powershell
.\windows-cache-cleanup.ps1 -Auto -ThresholdGB 20 -MinAgeDays 7
```

Порог относится к **старым файлам, которые разрешено удалить сейчас**, с учётом работающих приложений. При достижении порога удаляются все подходящие файлы из списка. Возраст проверяется и по времени создания, и по последнему изменению. Минимум — 1 день, по умолчанию — 7 дней. Удаление без корзины; содержимое кэшей приложения создают заново, иногда при следующем запуске потребуется время или повторная загрузка.

## Автоматический запуск

Сначала можно установить расписание, которое только составляет отчёты:

```powershell
.\manage-task.ps1 -Action Install -ReportOnly
```

В этом режиме не удаляются ни кэши, ни старые отчёты. Чтобы включить очистку, переустанови расписание без `-ReportOnly`:

```powershell
.\manage-task.ps1 -Action Install -ThresholdGB 20 -MinAgeDays 7
.\manage-task.ps1 -Action Status
```

Планировщик проверяет объём ежедневно в 10:00 и через 10 минут после входа в Windows. Время можно изменить: `-DailyAt 14:30 -LogonDelayMinutes 15`. Задача работает только в сеансе текущего пользователя, без повышения прав, без пробуждения компьютера. Установка сама не запускает очистку; параметр `-Disabled` создаёт выключенное расписание для проверки.

Код и отчёты хранятся в `%USERPROFILE%\.windows-cache-cleanup`. Этот путь доступен и обычному PowerShell, и планировщику, даже если установщик запущен из приложения, которое перенаправляет запись в AppData. Обновления из интернета не скачиваются. После обновления репозитория повтори установку.

Каждая версия кода и настроек получает отдельную папку. При переустановке сначала готовятся новые файлы, затем переключается задача. Если регистрация не удалась, прежняя задача восстанавливается. Старые версии остаются нетронутыми; существующую папку с изменённым содержимым установщик не перезаписывает. Расписание предыдущей версии с известным действием обновляется автоматически, старые файлы в AppData сохраняются. Посторонняя задача с таким же именем не заменяется.

Пауза и возобновление:

```powershell
.\manage-task.ps1 -Action Pause
.\manage-task.ps1 -Action Resume
```

Пауза запрещает будущие запуски, текущему позволяет завершиться. Переустановка сохраняет выключенное состояние задачи: для включения понадобится `Resume`. `Status` показывает состояние, параметры и последний отчёт.

Отключение:

```powershell
.\manage-task.ps1 -Action Remove
```

Это удаляет только задачу планировщика. Локальные скрипты и отчёты остаются. `-WhatIf` поддерживается и установщиком. Если Windows не разрешает зарегистрировать задачу, установщик сообщает об ошибке; права автоматически не повышаются.

## Что входит в список

| Категория | Что удаляется |
| --- | --- |
| Minecraft Bedrock / Skydimo | `ContentLog*.txt`, журналы `.log` и `.log.1` только в известных папках журналов |
| Adobe | Звуковые кэши `.cfa`, `.pek`, `.ims`, After Effects `Disk Cache-*.noindex` в известном пути Adobe |
| pip / npm / Gradle | Стандартные папки загрузок и кэшей текущего пользователя |
| NVIDIA / DirectX | Стандартные кэши шейдеров; установленные драйверы не затрагиваются |
| Chrome / Edge | `Cache`, `Code Cache`, `GPUCache` стандартных профилей |
| VS Code / Cursor | Только указанные в коде папки кэша вне `User` |
| Telegram | Только `tdata/user_data[#N]/cache` |
| FiveM | Только `cache`, `server-cache`, `server-cache-priv` |
| CapCut | Кэш; старые версии старше 30 дней при надёжном определении установленной версии |

У CapCut сохраняются установленная версия, предыдущая и все более новые версии. Папки версий с хотя бы одним свежим файлом сохраняются целиком. Пустые папки после удаления файлов могут оставаться. Необычные пути установки скрипт не ищет по всему диску.

С `-IncludeInstallers` дополнительно разрешены старые пакеты Minecraft в `levilauncher.exe/installers` и загрузки установщиков NVIDIA в известных каталогах `ota-artifacts`. Минимальный возраст этих файлов — **30 дней**. Можно добавить этот параметр и при установке расписания.

## Границы очистки

- **Unity не очищается вообще**: ни `Library`, ни временные проекты, ни сборки. Очистка Unity требует отдельного согласованного окна обслуживания: отсутствие процесса в момент проверки не гарантирует, что сборка не запустится через секунду.
- Нет очистки всего `Temp`, папок проектов, Git, документов, загрузок пользователя, корзины, виртуальных дисков, миров Minecraft и монтажных проектов.
- Пароли, cookies, история браузеров, авторизация Telegram, настройки приложений, VPN и базы проектов не входят в правила.
- Для известных приложений проверяются процессы при сканировании и во время удаления. Приложения не закрываются принудительно. Эта проверка не является блокировкой запуска приложений.
- Каждый файл открывается эксклюзивно и проверяется повторно: физический путь, размер, возраст, тип. Занятые, изменившиеся, защищённые и недоступные файлы пропускаются. Права доступа не меняются.
- Символические ссылки, junction и другие reparse points не обходятся. Файлы с несколькими жёсткими ссылками сохраняются.
- Нет рекурсивного удаления каталогов в очистителе. Нет телеметрии, отправки данных, реестрового «ускорения» и выключения служб.

Запускай от обычного пользователя. Для недоступного кэша показывается пропуск; административный запуск для штатной работы не нужен. После очистки шейдеров возможна временная компиляция; после очистки медиа потребуется повторное построение кэша. Adobe описывает восстановление файлов кэша в [документации Premiere](https://helpx.adobe.com/premiere/desktop/troubleshooting/media-issues/manage-media-cache.html).

## Локальные отчёты и приватность

```powershell
.\windows-cache-cleanup.ps1 -ReportPath "$env:USERPROFILE\.windows-cache-cleanup\reports\manual.json"
```

Отчёт создаётся только по явному пути; существующий файл не перезаписывается. Планировщик сохраняет отдельный JSON для каждого запуска; ошибка выполнения очистителя получает отдельный `*-error.json` и ненулевой код завершения задачи. После запуска с очисткой сохраняются минимум 30 последних служебных отчётов и все отчёты моложе 30 дней. Удаляются только файлы с точным служебным шаблоном имени в папке отчётов; занятые файлы пропускаются, произвольный `manual.json` сохраняется. Режим `-ReportOnly` старые отчёты не удаляет.

**В локальных отчётах есть абсолютные пути и имена файлов в сообщениях об ошибках.** Их нельзя публиковать без проверки. `.gitignore` исключает отчёты, JSON, дампы, журналы и резервные копии, но это дополнительная защита, а не проверка содержимого произвольного коммита.

В репозитории только обобщённый код, документация и синтетические тестовые данные. Сам скрипт не читает содержимое кэшированных документов, сообщений, браузерных баз или VPN-конфигураций. Для определения версии CapCut читается только `ProductInfo.xml`.

## Проверка

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\windows-cache-cleanup.test.ps1
pwsh -NoProfile -File .\windows-cache-cleanup.test.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\manage-task.test.ps1
pwsh -NoProfile -File .\manage-task.test.ps1
```

Тесты создают отдельные временные профили с искусственными файлами. Проверяются порог и возраст, сохранность проектов и авторизации, блокировки, смена файлов, запуск приложения после сканирования, junction, жёсткие ссылки, read-only, версии CapCut и необязательные установщики. Дополнительно проверяются откат установки, сохранение паузы, параметры расписания, режим отчётов и их хранение. Реальный профиль при тестировании не очищается.

`scheduler-native.test.ps1` отдельно проверяет настоящую регистрацию и обновление выключенной временной задачи Windows. Она не запускает очиститель и удаляется после проверки; для этой проверки Windows может потребовать административные права. CI выполняет её вместе с остальными тестами.
